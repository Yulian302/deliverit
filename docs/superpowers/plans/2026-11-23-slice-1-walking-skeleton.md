# Slice 1 — Walking Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A request `GET /v1/restaurants?near=lat,lng` travels Gateway → (Connect-RPC) → Order → Postgres and back, runs in docker-compose with the full local infrastructure, shows up as one trace in Grafana, and passes CI.

**Architecture:** One Go module. Shared, generic code lives in `platform/` (config, logging, OTel, health, HTTP server and middleware, graceful shutdown, Postgres). Each service lives in `services/<name>/` with its code under `internal/`, so other services can't import it. The Order service hosts the restaurant catalog as its own package (`internal/catalog`), split into service (logic) → store (sqlc) → rpc (transport).

**Tech Stack:** Go 1.26, Connect-RPC (`connectrpc.com/connect`, `otelconnect`), protobuf + `buf`, Postgres 17 + `pgx/v5` + `sqlc` + `goose`, `log/slog`, OpenTelemetry (OTLP gRPC) → `grafana/otel-lgtm`, `caarlos0/env/v11`, `testcontainers-go`, docker-compose, GitHub Actions.

**Spec:** `docs/SPEC.md` (approved). This plan covers PLANNING slice 1 only. The spec sections it implements: §6 (layout for Gateway/Order), §9.1 (timeouts used so far), §9.3 (graceful shutdown), §9.4 (health), §9.5 (tracing/logs), §13 (repo layout, tooling, boundaries, CI).

## Prerequisites (the human does these once, before Task 1)

- **Docker inside WSL:** `docker --version` and `docker compose version` must work in the WSL shell. Either enable *Docker Desktop → Settings → Resources → WSL integration* for this distro, or install Docker Engine in WSL.
- `gcc` is **not** required: `sqlc` runs via its Docker image.

## Global Constraints

- Module path: `github.com/Yulian302/deliverit`. `go 1.26` in `go.mod` (OpenTelemetry v1.47 requires it; `GOTOOLCHAIN=auto` fetches it).
- Code under `services/<svc>/internal/` is never imported by another service. `platform/` never imports `services/`. Enforced by `depguard` in `.golangci.yml`.
- Services never import transport or DB packages from their service layer (`internal/catalog/service.go` imports neither `net/http`, `connectrpc.com/*` nor `github.com/jackc/*`).
- Only parameterized SQL, generated by `sqlc`. Never hand-edit generated files (`gen/`, `**/dbgen/`).
- Timeouts: Gateway request deadline **5s**; `http.Server` `ReadHeaderTimeout` **5s**, `IdleTimeout` **60s**; DB statement timeout **1s**; graceful shutdown grace **20s**.
- Health endpoints on every service: `/livez`, `/readyz`. Readiness fails while draining.
- Logs: `log/slog` JSON with `service`, `trace_id`, `span_id`, `request_id` when available.
- Errors at the public edge: RFC 9457 `application/problem+json` with a stable `code` field.
- Config only through environment variables. No secrets committed.
- Dev tools pinned with `go get -tool` (except `sqlc` and `golangci-lint`, which run from Docker images pinned to exact tags in the Makefile).
- Commit messages carry **no** `Co-Authored-By: Claude` trailer (author's instruction).

## Review Focus

1. **Postgres not ready when Order starts** (common in compose): Order must keep running, report `/readyz` 503, and become ready when the DB is reachable. It must not crash-loop. → Task 5 (`TestPoolReadyCheck_FailsWhenDBDown`) and Task 8 (connect with retry).
2. **Malformed query params** (`near=abc`, `near=91,0`, missing `near`, `limit=-1`): must be `400` problem+json with `code: "invalid_argument"`, never a 500. → Task 9.
3. **Order service unreachable or slow:** Gateway must answer `503 upstream_unavailable` (or `504 upstream_timeout` once the 5s deadline passes), never hang. → Task 9.
4. **SIGTERM while a request is in flight:** the request completes with 200; new connections are refused; the process exits cleanly. → Task 3.
5. **Client sends a junk `X-Request-ID`** (more than 64 chars or characters outside `[A-Za-z0-9._-]`): it's replaced with a generated ID instead of being logged or echoed. → Task 3.

  LIMIT @lim::int;
